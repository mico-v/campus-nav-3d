本轮分支 `feat/m1-building-data`，数据源：
- `placeEdges.csv`：47 地点邻接矩阵（带米数），来自 [usts-navigation-graph](https://github.com/ZDaneel/usts-navigation-graph) master。

## 五、M2 室内店面落地记录（PR #66 / #68）

**做了什么**（都在 main 上，已可复现）：

- `CampusFloor` 增加可选 `rooms?: CampusRoom[]`（`id / name / aliases? / kind? / polygon?`），旧 pack 不填照常通过校验。
- 二食堂样板数据：1F = KFC / 面点档口 / 热炒档口，2F = 肯悦咖啡；`id` 与 7 条 indoor POI 的 `parentBuilding` / `floor` 一一对应，没有第二套名字。
- 页面可点选：选中二食堂 → 楼层条 1F/2F → 店面列表 → 点 KFC 详情标题 `KFC（二食堂店）`；无 rooms 的建筑不出现空列表。

**为什么不做墙体/家具/3D**：参考 studev 的口径（见 `docs/external/studev-review.md`），它的室内也只有「楼板 + 房间多边形 + 竖向交通点」。我们连多边形都还没填，只到「名字 + 楼层」这一层，已够回答「这栋楼里有什么店」。

**落地时挖出的真问题**：静态数据源只从建筑派生 POI，pack 里的 indoor 店面 POI 原本**没有进运行时 `data.pois`**，所以光接点击回调，点 KFC 会被静默忽略。现按 floors / connectors 同样的「运行时内存补齐」机制解决。
